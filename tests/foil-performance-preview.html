Five foil renderers: cheapest to costliest measured CPU work

Preview only: production rendering and saved settings are unchanged. Compare the same foil on light and dark cards, then run each renderer alone in the scrolling test. Ranked by main-thread work measured in the shared desktop browser, not universal GPU cost. Use the scrolling test to compare on your device.

Recorded desktop measurements

26 cards, rainbow foil, light/dark styles, 100 × 150 CSS pixels per card. Idle enabled except in the two static variants. Two runs per version in opposite orders; each run has 0.6 seconds of warm-up and a three-second scrolling sweep. Mean results below were measured on October 25, 2026 in VS Code's integrated browser: Chromium 150 / Electron 43, Windows, 655 × 1036 viewport, DPR 1, 16 logical cores.

Reports requestAnimationFrame intervals, not GPU paint timings or a guaranteed FPS gain. Browser scheduling, screen refresh rate and other tabs affect results. Reduced motion disables idle effects and the automatic sweep; manual scrolling still works.

What changes: the cached version flattens the card artwork, foil gradients, filters and blend modes into one self-contained SVG image, which the browser can rasterize and reuse. Only a small reflection transform animates outside the image. Its texture no longer shifts independently with the light. The simpler CSS version replaces the elaborate texture with a rainbow wash and repeating lines; it is intentionally less faithful.

All versions keep foil visible while scrolling. No canvases, WebGL contexts, remote assets, production changes or saved preference changes are introduced by this preview.
